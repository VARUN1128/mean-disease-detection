# AquaVeritas Backend API

FastAPI backend for fish disease detection using TensorFlow, Google Gemini AI, and Supabase.

## Features

- 🐟 **AI-Powered Disease Detection**: TensorFlow MobileNetV2 model for classifying 7 fish diseases
- 🤖 **AI-Generated Descriptions**: Google Gemini API provides medically accurate disease descriptions and treatment recommendations
- 📊 **Database Integration**: Supabase for storing users, predictions, and logs
- 📁 **Image Storage**: Automatic upload to Supabase Storage (optional)
- 🚀 **Public API**: `/predict` endpoint is publicly accessible (no authentication required)
- 📝 **Comprehensive Logging**: Track all predictions and API interactions

## Tech Stack

- **Python 3.9+**
- **FastAPI** - Modern, fast web framework
- **TensorFlow 2.16** - Deep learning model inference
- **Google Gemini AI** - AI-powered disease descriptions and treatment recommendations
- **Supabase** - Database, authentication, and storage
- **Pillow** - Image processing
- **Uvicorn** - ASGI server

## Setup Instructions

### 1. Prerequisites

- Python 3.9 or higher
- Supabase account and project
- TensorFlow model file (`.h5` format)

### 2. Install Dependencies

```bash
cd backend
pip install -r requirements.txt
```

### 3. Configure Environment

1. Copy `env.template` to `.env`:
```bash
# On Windows (PowerShell)
Copy-Item env.template .env

# On Linux/Mac
cp env.template .env
```

2. Update `.env` with your credentials:
```env
# Supabase Configuration
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your_anon_key_here
SUPABASE_SERVICE_KEY=your_service_role_key_here

# Model Configuration
MODEL_PATH=models/fish_disease_model.h5

# Google Gemini API Configuration
GOOGLE_API_KEY=your_google_api_key_here

# Server Configuration
HOST=0.0.0.0
PORT=8000
DEBUG=True
```

**Getting a Google Gemini API Key:**
1. Go to [Google AI Studio](https://makersuite.google.com/app/apikey)
2. Sign in with your Google account
3. Click "Create API Key"
4. Copy the API key and add it to your `.env` file

### 4. Set Up Supabase Database

1. Go to your Supabase project dashboard
2. Navigate to SQL Editor
3. Run `supabase_schema.sql` to create all tables
4. Run `seed_diseases.sql` to populate disease data

### 5. Create Storage Bucket

1. Go to Storage in Supabase dashboard
2. Create a new bucket named `fish-uploads`
3. Set it as **Public** (or configure policies as needed)

### 6. Place Model File

Place your TensorFlow `.h5` model file in the `backend/models/` directory, or update `MODEL_PATH` in `.env` to point to your model location.

### 7. Run the Server

**Development mode:**
```bash
uvicorn app:app --reload --host 0.0.0.0 --port 8000
```

**Production mode:**
```bash
uvicorn app:app --host 0.0.0.0 --port 8000 --workers 4
```

The API will be available at `http://localhost:8000`

## API Endpoints

### Prediction

#### `POST /predict`
Predict fish disease from uploaded image. **Public endpoint (no authentication required).**

**Request:**
- `file`: Image file (multipart/form-data)

**Response:**
```json
{
  "prediction": "Bacterial Gill Disease",
  "confidence": 0.92,
  "description": "Bacterial gill disease is a common infection affecting freshwater fish, characterized by inflammation and damage to the gill tissue. It typically occurs in environments with poor water quality, high ammonia levels, or overcrowding. Symptoms include labored breathing, gill discoloration, and reduced activity.",
  "recommended": "Oxytetracycline: 50-100 mg per liter of water for 5-7 days. Administer as a bath treatment. Maintain optimal water quality with low ammonia levels. Increase aeration during treatment.",
  "disclaimer": "Disclaimer: This is AI-generated information and not a medical diagnosis. Consult a certified aquaculture veterinarian."
}
```

**Note:** The `description` and `recommended` fields are generated by Google Gemini AI based on the predicted disease. If the Gemini API is unavailable, fallback messages will be returned.

### Diseases

#### `GET /diseases`
Get list of all diseases.

**Response:**
```json
[
  {
    "id": "uuid",
    "name": "Bacterial Gill Disease",
    "description": "Bacterial infection affecting the gills...",
    "common_treatment": "Bath treatment: Maintain low ammonia...",
    "medicine_suggestion": "Oxytetracycline: 50-100 mg..."
  }
]
```

#### `GET /diseases/{disease_id}`
Get detailed information about a specific disease.

#### `GET /diseases/name/{disease_name}`
Get disease information by name.

### Health Check

#### `GET /health`
Check API health status.

#### `GET /`
Root endpoint with API information.

## Security Notes

- The `/predict` endpoint is publicly accessible (no authentication required)
- CORS is currently configured to allow all origins (update for production)
- Row Level Security (RLS) is enabled on all Supabase tables
- Service role key should be kept secret and only used server-side
- Google Gemini API key should be kept secure and never exposed in client-side code

## Model Information

The backend expects a TensorFlow `.h5` model file that:
- Accepts input images of size 224x224 (RGB)
- Outputs predictions for 7 disease classes:
  1. Bacterial Gill Disease
  2. Aeromoniasis
  3. Parasitic
  4. Viral White tail
  5. Fungal Saprolegniasis
  6. Bacterial Red Disease
  7. Healthy Fish

## Troubleshooting

### Model not loading
- Ensure `MODEL_PATH` in `.env` points to a valid `.h5` file
- Check file permissions
- Verify TensorFlow version compatibility

### Gemini API not working
- Verify `GOOGLE_API_KEY` is set in `.env`
- Check that the Generative Language API is enabled in Google Cloud Console
- Ensure your API key has proper permissions
- Check backend logs for specific error messages
- If Gemini fails, the API will return fallback messages

### Supabase connection errors
- Verify `SUPABASE_URL` and `SUPABASE_KEY` in `.env`
- Check network connectivity
- Ensure Supabase project is active
- Storage upload failures are non-critical - predictions will still work

### Storage upload failures
- Verify `fish-uploads` bucket exists in Supabase Storage
- Check bucket permissions (should be public or have proper policies)
- Ensure service role key has storage access
- **Note:** Storage upload failures are non-critical - the prediction will still work without storing the image

## Production Deployment

1. Set `DEBUG=False` in `.env`
2. Use a production ASGI server (e.g., Gunicorn with Uvicorn workers)
3. Configure proper CORS origins (update `ALLOWED_ORIGINS` in `.env`)
4. Use environment variables for all secrets (never commit `.env` file)
5. Enable HTTPS
6. Set up proper logging and monitoring
7. Ensure Google Gemini API key has proper rate limits configured
8. Consider implementing rate limiting for the `/predict` endpoint
